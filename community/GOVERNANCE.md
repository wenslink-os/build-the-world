# Governance

Initial maintainers are the people named in the eventual hosting repository. This archive does not appoint or impersonate maintainers.

Discuss substantial changes through public RFC pull requests. At least one maintainer reviews educational accuracy, test coverage and license provenance before merge. Security issues use private reporting. Routine typo fixes can use a single review.

A contributor may request maintainer status after sustained high-quality reviews and contributions. Existing maintainers publish the decision and rationale. Conflicts of interest are declared; an uninvolved maintainer handles conduct appeals when available.

Keep roadmaps and release notes public. Credit contributors for accepted work. Monetization must never make the core local curriculum depend on a paid API or mandatory account.
