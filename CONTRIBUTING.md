# Contributing

Start with a contract, a failing test, or a clearer explanation.

## Add a lab

1. Run `node bin/btw.mjs create your-topic` to generate metadata under `contributions/`.
2. Specify exact input/output rules and boundaries. Keep examples executable.
3. Add `starter/solution.mjs`, `solution/solution.mjs` and `broken/solution.mjs` under `challenges/your-topic/`.
4. Add acceptance cases to `challenge.json`. Each case receives the named exports, `equal`, `throws`, and `rejects`.
5. Copy the full challenge object into `web/catalog.json`, adding `starter` and `broken` source strings. The metadata test checks the source contract and cases agree.
6. Include a README with prerequisites, hints, limits and the failure explanation.
7. Run `node scripts/verify.mjs`. A reference must pass all cases. Its broken variant must fail at least one. A starter must not falsely pass.
8. Open a PR using the template.

The starter and solution API must match. Use injected clocks and deterministic inputs; no sleeping or network dependency in acceptance cases. Do not include credentials, destructive commands, copied unlicensed material, advertisement submissions or unfinished autogenerated packs. Platform maintainers review educational accuracy and test quality before merge.

## Challenge standard v1

`schemas/challenge.schema.json` describes the shape. The runtime only loads the bundled catalog. Third-party packs are not automatically trusted or executed. The current validator checks bundled ids, prerequisites and required files; it is not a generic JSON Schema interpreter. Review new case bodies as executable JavaScript.

## Translations

Add guides under `translations/<language>/`. Keep technical names and code unchanged. The v0.1.0 interface is English; Assamese documentation is included. Native speakers should review translations before they become official UI strings.

## Review checklist

- One focused learning goal with explicit boundaries.
- Tests include valid, invalid and boundary inputs.
- Broken implementation represents a documented defect.
- No misleading compatibility, performance or mastery claim.
- Keyboard navigation and narrow-screen layouts still work.
- Source metadata and web catalog stay aligned.

Submitting a contribution means licensing code under Apache-2.0 and prose under CC BY 4.0. State provenance for external material.
